2. Файл: deployment.yaml

Проблема: дивний запуск сервісу, не має обмежень безпеки

Опис: У маніфесті прописаний порт 8080, в той час як в докерфайлі стоїть 8000. До того ж перевірка livenessProbe переходить по адресі /health якої взагалі немає в коді. ,Також немає заборони працювати з правами суперкорист через securityContext

Рішення: Синхронізувати порти на 8000 та заборонити root на рівні поду
(ports:
    -containerPort: 8000
securityContext:
    runAsNonRoot: true
    allowPrivilageEscalation: false)
.
.
.
3. Файл: dockerfile

Проблема: Робота під root і відсутність контролю залежностей

Опис: У контейнера надто багато прав, якщо буде злам , то хакер отримає доступ і контроль над усім контейнером і тому щзо у ньому. Також встановлюються бібліотеки без номерів версій, тому кожен раз качається щось нове і без перевірки

Рішення: Створити систем ного користувача без root прав і запускати застосунок через нього + фіксучати версії через requirements.txt
(RUN useradd -u 10001 appuser
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
USER appuser)
.
.
.

5. Файл: main.tf

Проблема: Відкритий мережевий доступ до сервісу 

Опис: Порт 443 відкритий для усього інтернету, нема обмеження джерела трафіку лише через балансувальник та відсутні вихідні правила

Рішення: Обмежити вхідний трафік тільки з групи балансувальника та додати уgress правило
(ingress{
    from_port = 443
    to_port = 443
    protocol = 'tcp'
    security_groups = [aws_security_group.alb.id]}
    
    egress{
        from_port = 0
        to_port = 0
    protocol = '-1'
    cidr_blocks = ['0.0.0.0/0']
    })
